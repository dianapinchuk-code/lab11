# Правила для розробки ShowFinder

1. Домен та ендпоїнти: звертатися ТІЛЬКИ до https://api.tvmaze.com. Ніколи не використовувати www.tvmaze.com або сторонні CORS-проксі.
2. Прості GET-запити: надсилати виключно GET без жодних кастомних заголовків. НЕ ДОДАВАТИ `Content-Type: application/json` або `Accept` (це ламає preflight). Без `mode: 'no-cors'`.
3. Запит пошуку: завжди кодувати параметр через `encodeURIComponent` або `URLSearchParams`: `/search/shows?q=${encodeURIComponent(query)}`.
4. Дані серіалу: завантажувати за один запит із вбудованими зв'язками: `/shows/${id}?embed[]=episodes&embed[]=cast`.
5. Обробка відповідей:
   - Завжди перевіряти `response.ok`. Якщо `!response.ok` — не парсити як успішні дані.
   - Порожній масив `[]` при 200 — це НЕ помилка.
   - 404 для серіалу — це «Серіал не знайдено».
   - 5xx або помилка парсингу JSON — «Не вдалося отримати дані від TVmaze.».
   - Мережевий збій (відхилений fetch) — «Немає з’єднання з TVmaze.».
6. Рейтліміт (429): автоматично повторити запит ОДИН раз через 2–5 секунд. Якщо знову 429 — показати «Забагато запитів до TVmaze.» і кнопку «Спробувати ще».
7. AbortController: обов'язково скасовувати попередній запит при новому пошуку чи перемиканні серіалу. `AbortError` не вважається помилкою (не відображати помилку в UI, відловлювати без `console.error` чи `Uncaught`).
8. Тексти інтерфейсу: використовувати ВИКЛЮЧНО точні тексти зі специфікації (§3.4). Жодних англійських назв винятків чи системних alert.
9. Кешування: успішно отримані серіали зберігати в пам'яті (`Map`). Помилкові відповіді ніколи не кешувати.
